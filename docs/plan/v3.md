# v3.0.0: パススルー一本化とトークン単位の制限

## 目的

Rialto を「受け口で受けたリクエストを、指定されたモデルを持つプロバイダへそのまま送る」ゲートウェイに
絞る。誰が何を使えるかは、アクセストークンごとに決める。

- ルーティング(シナリオ・レーン・tier による振り分け)は使われていないので削除する。
- 既存の受け口・プロバイダ・サブスクリプション・利用ログ・`/codex` などはそのまま残す。

## 変更後の振る舞い

1. クライアントはアクセストークンを付けて、いずれかの受け口へリクエストする。
2. トークンが許可していない受け口なら拒否する(現在の `surfaces` と同じ)。
3. `body.model` のモデルを持つプロバイダを、今の passthrough と同じ規則で決める。重複は
   プロバイダの優先順位で解決し、`provider,model` 形式も引き続き受け付ける。
4. トークンに Plan が紐づいていれば、Plan の `models` で判定する。許可外のモデルは **403 で拒否する**
   (v2 では `defaultModel` へ振り向けていた)。モデル名が指定されていないときだけ `defaultModel` を使う。
5. Plan のレートリミットを超えていれば 429。
6. アップストリームへ送る。サブスクリプションの複数アカウント切り替えとフェイルオーバーは今のまま。

## アクセストークンと Plan

構造は変えない。トークンは受け口と Plan を選び、Plan がモデルとレートリミットを決める。

| 設定 | 持ち主 | 内容 | 空のとき |
|---|---|---|---|
| 対応エンドポイント | トークン(`surfaces`) | 受け口 id の一覧 | すべて許可 |
| 利用できるモデル | Plan(`models` / `defaultModel`) | `provider,model` の一覧 | Plan なしなら制限なし |
| レートリミット | Plan(5時間・7日の窓ごとのリクエスト数と金額) | 既存の `AccessTokenUsageWindow` で集計 | 無制限 |

Plan は複数のトークンで共有でき、Plan を編集すると紐づく全トークンに次のリクエストから反映される。
v3 で足すのは、トークンの発行・編集画面でこの3つを並べて選べるようにすること(Plan をその場で
作成するショートカットを含む)。

## 削除するもの

- `routed` モード、シナリオ・レーン・tier の分類、TierRoute、プロファイル、tier エイリアス、
  Long context チューナー、subagent レーンの切り替え(タグの除去と `isSubagent` の記録は残す)。
- ルーティング画面、Overview などにあるルーティング表示、ルーティング関連の API。
- `routing-scheduler` のうち、ルートの並べ替えにだけ使うもの。アカウント切り替えが依存している部分は
  残し、実装時に切り分けを確認する。

## データベース

新しいマイグレーションを1本追加する。**Plan とトークンのデータは変更しない。**

- 削除: `AccessToken.profileKey`、`RouterPreferenceProfile`、`TierRoute`、`ProviderTierAlias`、
  `InboundSurfaceConfig.routingMode` / `profileKey`。
- 既存の `routed` 設定は捨てる。すべての受け口が passthrough になる。

## PR の分け方

1. `refactor(routing)`: routed モードとルーティングのバックエンドを削除し、常にパススルーにする。
   DB マイグレーションを含む。
2. `refactor(ui)`: ルーティング画面とルーティング表示を削除する。
3. `feat(access)`: トークンの発行・編集画面で受け口・Plan・上限をまとめて選べるようにする。モックを先に作る。
4. `docs`: architecture・guides・README・CLAUDE.md を更新する。
5. `chore: bump version to 3.0.0` → リリース → RTX5060 マシンの更新。

各 PR で `tsc`・biome・knip・テスト・build を通す。

## 決定事項

- 許可外のモデルは 403 で拒否する(2026-11-13 決定)。振り向けは廃止する。この挙動変更は v3 の
  破壊的変更なので、リリースノートに書く。
